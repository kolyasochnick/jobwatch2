# JobWatch — мониторинг новых вакансий на сайтах компаний

Раз в 3 часа (настраивается) обходит сайты из `companies.json`, оставляет вакансии нужного грейда и направления
(`config.json`) и присылает на почту **одно письмо-дайджест** только о тех, которых раньше не было.
Работает на GitHub Actions — ваш компьютер не нужен.

## Как это устроено

| Файл | Назначение |
|---|---|
| `companies.json` | Список компаний и способ их разбора (вы редактируете). Шаблоны всех типов — в `companies.examples.json` |
| `config.json` | Грейд, направление, исключения, поведение первого запуска |
| `state/seen.json` | Память: что уже отправлялось. Обновляется ботом сам |
| `.github/workflows/check.yml` | Расписание и запуск |
| `jobwatch/` | Код |

**Гарантии:** письмо не ушло → состояние не сохраняется, и вакансии придут в следующий раз.
Сайт сломался → остальные проверяются дальше; после 3 сбоев подряд придёт письмо-предупреждение.

## Развёртывание за 10 минут (GitHub Actions)

1. Создайте на GitHub **приватный** репозиторий и загрузите туда содержимое этой папки
   (`git init && git add . && git commit -m init && git remote add origin … && git push -u origin main`).
2. **Почта (Gmail):** включите двухфакторную аутентификацию → https://myaccount.google.com/apppasswords →
   создайте «пароль приложения» (16 символов). Обычный пароль не подойдёт.
3. В репозитории: *Settings → Secrets and variables → Actions → New repository secret*. Создайте:

   | Secret | Значение (Gmail) | Яндекс |
   |---|---|---|
   | `SMTP_HOST` | `smtp.gmail.com` | `smtp.yandex.ru` |
   | `SMTP_PORT` | `465` | `465` |
   | `SMTP_USER` | ваш адрес | ваш адрес |
   | `SMTP_PASSWORD` | пароль приложения | пароль приложения |
   | `MAIL_TO` | куда слать (можно несколько через запятую) | то же |

4. *Settings → Actions → General → Workflow permissions* → **Read and write permissions** → Save.
5. Вкладка *Actions → Check vacancies → Run workflow*, поставьте галку **test_email** — должно прийти тестовое письмо.
6. Заполните `companies.json` и `config.json`, запустите ещё раз без галки. Дальше всё идёт само.

Заметки по GitHub Actions: расписание может запаздывать на 5–30 минут; в публичных репозиториях GitHub
отключает расписание после 60 дней без активности (коммиты бота с состоянием обычно её поддерживают,
но если отключит — включите вручную на вкладке Actions). О провале запуска GitHub сам пришлёт письмо.

## Как добавить компанию

Добавьте объект в `companies.json`. Поддерживаемые `type`:

* **`greenhouse`** — `"board"`: часть после `boards.greenhouse.io/` (или `job-boards.greenhouse.io/`).
* **`lever`** — `"board"`: часть после `jobs.lever.co/`; для EU-аккаунтов добавьте `"region": "eu"`.
* **`workable`** — `"account"`: часть после `apply.workable.com/`.
* **`hh`** — `"employer_id"` из адреса `hh.ru/employer/<id>`; доп. параметры поиска в `"params"`, например `{"text": "python"}`.
* **`json`** — любой JSON API: `url`, `items_path`, `title_field`, `url_field` или `url_template`, `location_field`.
* **`html`** — обычная страница. Без селекторов берутся все ссылки страницы и фильтруются по ключевым словам.
  Для точности укажите CSS-селекторы (DevTools → правый клик по вакансии → Inspect):
  `item_selector`, `title_selector`, `link_selector`, `location_selector`.
  Пагинация: `"url": "https://…?page={page}"`, `"max_pages": 5`. Если в ссылках есть мусор (utm и т. п.) — `"strip_query": true`.
* **`playwright`** — сайт на JS (вакансии подгружаются скриптом): страницу открывает настоящий браузер.
  Параметры: `wait_for`, `load_more_selector` + `load_more_clicks` (кнопка «показать ещё»), `scroll` (макс. число прокруток;
  останавливается, когда страница перестала расти).
  **Без `item_selector` включается автоопределение:** браузер перехватывает JSON-запросы сайта, находит среди них список
  вакансий и разбирает его сам — подходит для новых сайтов, у которых вы не знаете структуру. Подсказки при необходимости:
  `api_filter` (кусок адреса нужного API), `title_field`, `url_field` / `url_template` (например `https://site.ru/vacancy/{id}`).
  Если JSON не найден — берутся все ссылки страницы.
  Браузер ставится в Actions автоматически, если в файле есть хотя бы один `playwright`.
* **Общие для html/playwright:** `url_regex` — оставлять только ссылки, подходящие под регулярное выражение (отсекает меню и
  фильтры); `context: "card"` — для фильтра брать текст всей карточки вакансии (уровень «Junior», теги), а не только заголовок.

Отключить компанию: `"enabled": false`. Ключи, начинающиеся с `_`, игнорируются (удобно для заметок).

**Проверка нового источника локально:**
```bash
pip install -r requirements.txt
python -m jobwatch --company "Имя компании" --dry-run -v
```
`--dry-run` ничего не отправляет и не сохраняет — просто показывает, что нашлось.

## Отладка нового источника

Actions → *Check vacancies* → *Run workflow* → галка **debug** (и, по желанию, имя компании в поле *company*).
В логе будет список **всех** найденных вакансий, ✓ отмечает прошедшие фильтр; ничего не отправляется и не сохраняется.
Для `playwright`-сайтов без селекторов в логе видно, какой API выбран. Если нашлось 0 вакансий или не те — пришлите мне
этот лог, и я подберу настройки. Локально то же самое: `python -m jobwatch --dry-run --show-all -v --company "Имя"`.

## Как работает фильтр

Заголовок вакансии должен содержать слово из `grade.include` **и** слово из `direction.include`
и **не** содержать слов из `exclude`-списков. Слова ищутся как *начало слова* без учёта регистра:
`ведущ` найдёт «ведущий/ведущего», `lead` не сработает на «Misleading». Пустой список = условие не проверяется.
`locations` (если заполнен) проверяется только у вакансий, где сайт отдаёт локацию.

`on_new_company`: `"notify"` — при первом появлении компании прислать все текущие подходящие вакансии;
`"baseline"` — молча запомнить их и писать только о появившихся позже.

## Альтернатива: свой VPS

```bash
docker build -t jobwatch .
# в cron (crontab -e), раз в 3 часа:
17 */3 * * *  cd /opt/jobwatch && docker run --rm --env-file .env -v "$PWD":/app jobwatch
```
Файл `.env` создайте из `.env.example`. Состояние хранится в `state/seen.json` на диске сервера.

## Важно: российские сайты и GitHub Actions

Серверы GitHub находятся за пределами России. Часть российских сайтов (особенно с антибот-защитой — Авито, Ozon, X5)
может отдавать им ошибки 403/капчу или не открываться. Проверьте это первым debug-запуском. Если так — запускайте
тот же проект на недорогом VPS в России (см. раздел про VPS выше): код менять не нужно.

## Ограничения и этика

* Соблюдайте условия использования и `robots.txt` сайтов, не ставьте слишком частые проверки (3 часа — разумный минимум).
* hh.ru может требовать авторизацию для API и иногда блокирует IP дата-центров (в т. ч. GitHub). Если так — получите
  токен приложения и положите в secret `HH_TOKEN`, либо используйте страницу компании через тип `html`/`playwright`.
* Сайты с капчей или жёсткой защитой от ботов этим инструментом не разобрать.
* Если селекторы сломались (сайт переверстали), в логе будет «0 вакансий», а после 3 сбоев придёт предупреждение.
